## Immutable source recommendation v1

Recommend moving **SCKRL-312 to Review only** for the frozen source increment below. This accepts
source readiness for continued database, connected and native review under the ratified v2
contract. It does not mark the ticket Done, satisfy Stage 1 exit, or accept any unexecuted gate.
SCKRL-304 and SCKRL-406 retain their own Review states and runtime/native gates.

The prepared additive migration owns receipt-line unknown/dated/no-date choices within the
existing generation/revision-guarded save, preserves expiry when older clients omit it, rejects
invalid combinations and forged attribution, and updates expiry-specific actor/time only on
actual normalized change. Shared and web payloads retain explicit state/date intent. Historical
migrations were not edited. SQL and fixture source have been inspected; they have not executed.

The mobile review offers optional accessible expiry choices, validates real Gregorian dates,
retains the stored calendar day for display, resets included-line review after expiry changes,
and preserves drafts across conflict, uncertain saves and same-account token refresh. A clean
saved snapshot alone offers **Done for now** to Home. The route uses the installed native-stack
`usePreventRemove` boundary, prevents departure during an in-flight save, requires explicit
discard/reload for unconfirmed changes, and uses scoped callbacks. The visible **No expiry date**
helper distinguishes intentional no-date recording from **Unknown**. Success says **Review saved.
Items are not in stock yet.**

Home discovers persisted saved active reviews through the current authenticated household,
pages beyond the initial three entries, revalidates the same receipt before opening, and guards
async responses and settlement by account/token, focus, request and household binding. Recoverable
errors preserve existing entries and expose retry. This source supports durable resume; an actual
app restart and connected persistence are still unverified.

The increment creates no stock and keeps placement unavailable. SCKRL-311 must implement locked
stock conversion, acquisition events, source-line lineage, placement idempotency/result recovery,
authoritative placed filtering and post-placement review immutability. Those remain contract-only
and are not accepted by this source recommendation. No review confirmation is transferred to a
placer; no automatic receipt estimate or reminder scheduling is implemented.

The independent final source review reports no remaining blocking source finding. Root and QA
checks in the evidence section support this bounded Review recommendation. They do not prove SQL
constraints, Auth/PostgREST enforcement, native interaction or actual restart recovery.

The strongest counterargument is that passing mocked/source checks cannot establish durable
expiry or safe native exit. It is supported. The response is a **Review** checkpoint with the
named gates still open, rather than Done or runtime acceptance. Keeping In Progress until
authorized runtime work is possible is an alternative, but obscures that source implementation
is ready for its remaining review. Expanding immediately into SCKRL-311 is another alternative;
it would bypass the deliberately separate placement scope.

No migration application or replay, hosted write/configuration, deployment, commit or merge is
authorized by this recommendation. The new client mapping requires the migrated expiry schema
and rejects an unmigrated response; no backward compatibility with an unmigrated database is
claimed.
